### Шаг 1. Создание оформления через layout.tsx

В Next.js есть специальный файл `layout.tsx`. Если положить его в папку, он автоматически «оденет» в свой дизайн все страницы внутри этой папки и всех вложенных папок. Это идеально подходит для нашей задачи.

**Что нужно сделать в VS Code:**
1. Найдите папку `src/app/i/`.
2. Создайте в этой папке (`/i/`) новый файл и назовите его **`layout.tsx`**.
3. Вставьте в него этот код:

```tsx
export default function DesignerLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <div style={{ 
      backgroundColor: 'blue', 
      color: 'white', 
      minHeight: '100vh',
      padding: '20px' 
    }}>
      {children}
    </div>
  )
}
```

**Разбор кода:**
* `export default function DesignerLayout` — создание шаблона (лейаута), который будет общим для всех подпапок внутри `/i/`.
* `{children}` — специальная команда, которая говорит: «вставь сюда содержимое конкретной страницы».
* `style={{...}}` — встроенные стили (CSS):
    * `backgroundColor: 'blue'` — устанавливает синий фон.
    * `color: 'white'` — делает текст белым.
    * `minHeight: '100vh'` — растягивает синий фон на всю высоту экрана.

    * **Контекст:** После настройки собственного цвета фона в коде страницы, в браузере отображался другой серый оттенок.
    * **Причина:** Вмешательство файла `src/app/globals.css`. В стандартных шаблонах Next.js там прописаны базовые стили для светлой и тёмной тем, которые перекрывают пользовательские настройки.
    * **Решение:** Полная очистка содержимого `globals.css`. Для предсказуемого дизайна лучше оставить там только базовый сброс отступов (`margin: 0`).

* **Текст страницы игнорирует настройки цвета из файла Layout**
    * **Контекст:** Цвет текста, заданный в общем шаблоне (`layout.tsx`), не применялся к заголовкам на страницах или не менялся при попытке создать исключение.
    * **Решение:** Переход на использование **инлайновых стилей** (`style={{ color: '...' }}`) непосредственно в файле страницы (`page.tsx`). Этот метод имеет наивысший приоритет и гарантирует, что элемент примет нужный цвет.

* **Визуальный разрыв из-за смеси разных тегов (`div` vs `main`)**
    * **Контекст:** Страницы выглядели по-разному, потому что в одном файле использовался тег `<main>`, а в другом — `<div>`.
    * **Решение:** Унификация кода. Использование `<div>` во всех файлах как наиболее универсального и «предсказуемого» контейнера.

### ❓ Ответы на важные концептуальные вопросы

* **Почему в файлах возникла путаница: где-то был `<div>`, а где-то `<main>`?**
    Это произошло из-за смешивания источников кода. Стандартные шаблоны Next.js часто используют семантический тег `<main>` для обозначения основного контента. В то же время нейросети или быстрые примеры кода чаще используют универсальный `<div>`. В итоге в проекте возникла «смесь», которая и дала разное отображение в браузере.

* **Почему в современном коде нельзя использовать атрибуты типа `color="green"`?**
    В React и Next.js (JSX) старые HTML-атрибуты для оформления не поддерживаются. Дизайн задаётся через объект стилей: `style={{ color: 'green' }}`. Это позволяет динамически менять оформление через код.

* **В чём разница между файлами `layout.tsx` и `page.tsx`?**
    * `layout.tsx` — это «общая рама» (шаблон). Всё, что в нём написано, отображается на всех страницах данной папки и её подпапок.
    * `page.tsx` — это уникальный контент конкретного адреса.

* **Как создавать исключения в дизайне для похожих страниц?**
    Если нужно, чтобы одна страница в папке отличалась от других, мы можем либо передать новое значение через CSS-переменную из файла страницы в лейаут, либо (что проще и надёжнее на старте) переопределить стиль напрямую в файле `page.tsx` через атрибут `style`.

* **Допустимо ли использовать тег `div` для всего подряд?**
    Для обучения и быстрой сборки интерфейса — да. `div` является универсальным «прозрачным» контейнером без предустановленных стилей, что делает его удобным инструментом для начинающих, чтобы избежать неожиданных сдвигов верстки.
